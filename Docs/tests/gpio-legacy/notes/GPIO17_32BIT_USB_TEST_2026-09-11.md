# GPIO17：32 bit環境でのUSB連携・入力計数比較

実施日：2026-09-11。印刷なし。ファンは切断したまま、発信器による入力試験。

## 結論

WF1974のUSB制御、OWON VDS1022I CH1の波形取得、試験用PiへのSSH接続は動作した。一方、32 bit OSでもLow固定と50 Hz入力に対するGPIO17の過剰検出が再現した。今回の32 bit化だけでは問題は解消しない。

High固定では正常。IRQを要求していない時間のPython/CによるGPLEV0直接読み取りにも変化が現れるため、GPIOイベントAPIだけの問題とは絞れない。電気的な短時間の変動、Pi入力側、レジスタ読み取り経路等の原因は未確定であり、Pi故障やOSのバグを断定しない。

## 条件と安全確認

- Raspberry Pi 3 Model B Plus、armv7l / 32 bit、kernel 6.18.34+rpt-rpi-v7、gpiod 2.2.0。
- SSH：ホスト鍵照合済み。接続先、ユーザー名、パスワードは公開資料に含めない。
- WF1974：USB VID 0D4A / PID 000E、Ver2.30。OWON：VID 5345 / PID 1234。個体のシリアル番号は省略。
- 前回ユーザー確認の配線を維持した前提：WF CH1→R3 1 kΩ→GPIO17（物理11）、R4 10 kΩで3.3 Vにプルアップ、C2 103（公称10 nF）をGPIO17–Pi GND間。WF・Pi・オシロのGND共通、CH1 x1をGPIO17に接続。容量実測・配線の現物再確認は未実施。
- GPIO17を入力／内部プルなし、GPIO18を出力High（C1815反転回路の停止側）へ実行時のみ復元。共有PADは読み取りのみ、0x1b、ヒステリシス有効。
- 新OSでは従来の起動時ファン停止サービスはinactive。今回、起動設定は編集していないため、再起動後のファン停止維持は別途復元・検証が必要。
- WF設定：High-Z、通常50 Hz・50%・2.4 Vpp・+1.5 V。DC試験のみ出力OFF中にDC 0.3 V／2.7 Vへ変更し、終了時に元の矩形波設定へ復元。
- 各試験の前後に出力OFFで3秒のGPIO立上り計数を実施し、すべて0件。最後にWF CH1/CH2ともOFF、GPIO18 Highを確認。

## 32 bitでの結果：観測元を分離

| 入力条件 | オシロCH1の定常波形（25 kS/s） | Pi Python直接読取：変化数／約250 ms | Pi C直接読取：変化数／実時間 | Piカーネル立上りイベント |
|---|---|---:|---|---|
| Low固定 | 中央値0.58 V、0.50–0.64 V。解析しきい値の交差0回 | 264 | 8,192回／115.708 ms、保護上限 | 251件で中止。要求時間10.786 ms |
| High固定 | 中央値2.74 V、2.64–2.80 V。解析しきい値の交差0回 | 0 | 0回／250.000 ms、全読取High | 0件／504.203 ms |
| 50 Hz | Low 0.58 V／High 2.74 V、周期中央値約20 ms | 159 | 8,192回／178.131 ms、保護上限 | 251件で中止。要求時間15.767 ms |

カーネルイベントの251件は「50 ms内に250件超」の中止条件による打切り値。周波数・RPMへ換算しない。イベント保存区間はLowで1.639 ms、50 Hzで1.589 ms。要求時間には処理時間が含まれる。IRQ増分はLow 3,409、High 0、50 Hz 2,946であり、保存イベント数とは別の量。

C直接読取はvolatile uint32_tとメモリバリアを使用。両端のエッジ／レベル検出有効ビットは0で、能動的なIRQ要求前に測定。32 bit環境のコンパイラ既定ターゲットではdmb命令が組み立てられなかったため、確認済みarmv7lに限り -march=armv7-a -mfpu=vfpv3-d16 を指定した。初回コンパイル失敗試行は発信器出力ON前に終了し、比較から除外。

## 同じ103・GPIO17条件の64 bit版との比較

| 条件 | 64 bit（9月10日）Python変化／約250 ms | 32 bit（9月11日）Python変化／約250 ms | カーネルイベントの結論 |
|---|---:|---:|---|
| Low | 154 | 264 | 両方で251件の保護中止 |
| High | 0 | 0 | 両方で約0.5秒間0件 |
| 50 Hz | 87 | 159 | 両方で251件の保護中止 |

両OSのオシロ定常電圧はLow約0.58 V／High約2.74 Vで一致。各条件1試行であり、読み取り速度・コンパイラ・OSイメージ・実行時負荷等も異なる。数値の増加を「32 bitの方が悪い」という因果関係として扱わない。確実に言えるのは異常が32 bitでも再現したこと。

## 測定の限界と次の切り分け

25 kS/sのサンプル間隔は40 µsであり、オシロにしきい値越えが見えないことは、より短い変動が存在しない証明ではない。オシロとPiはハードウェア時間同期しておらず、電圧統計の解析窓もPiの取得窓と完全には一致しない。Python/Cのポーリングは不等間隔で、波形や校正されたエッジ時刻ではない。

次は32 bit環境でもLow固定中の高速波形測定を行い、今回の直接読取結果と比較するのが配線変更なしで可能な切り分け候補。その後、入力点とPi基準GNDの取り方を含む電気的な切り分けや別のPiでの比較を検討する。現段階ではファン実回転数のフィードバック成立は未確認。
