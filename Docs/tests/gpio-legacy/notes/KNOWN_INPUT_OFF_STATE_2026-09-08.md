# GPIO17再接続後：発振器OFF対照での異常

2026-09-08 16:32-16:35 JST。測定記録のみ。最終レポートの更新はユーザー指示により保留。

## 実施条件

ユーザーからGPIO17再接続の報告。先行案内どおりR3 1 kΩ経由、ファンTach切り離し、OSC CH1をGPIO17側とする前提。配線そのものを画像等で独立確認してはいない。

SSHでGPIO17入力High、GPIO18出力High、windtunnel-fan-stop.service activeを確認。発振器はWF1974、2.4 Vpp、+1.5 V、50 Hz、矩形波、独立・連続、外部加算OFF、High-Z、CH1/CH2とも出力OFFを読み戻した。

この一連の試験では発振器を一度もONにしていない。50 Hz波形のGPIO入力試験は未実施。

## Piのカーネルイベント

専用入力取得スクリプトをSSH stdin経由で実行。GPIO18やPWMには触れず、GPIO17だけを一時要求。libgpiod 2.2.0、デバウンスなし、bias AS_IS、MONOTONIC時刻。予定3 sのOFF対照は全試行で安全上限（250件超/50 ms）により約9-10 msで中断した。保存されたイベント列に連番欠落なし。

| 取得 | 立上件数 | 立下件数 | 間隔中央値 |
|---|---:|---:|---:|
| 初回OFF・両エッジ | 251 | 0 | 6.667 µs |
| OFF・立上のみ | 251 | 0 | 7.448 µs |
| OFF・立下のみ | 0 | 251 | 6.875 µs |
| OFF・両エッジ再試験 | 245 | 6 | 7.344 µs（全イベント） |

再試験の両エッジ列は同種エッジが隣接する組が240あり、通常の交互列ではない。取得前・中の値はHighだったが、両エッジ再試験の解放直後のLEVELレジスタ読取はLowとなった。したがってPiが全期間Highと読んでいたとは言えない。

検出レジスタは読み取り専用の/dev/gpiomemで確認した。要求中は立上のみならRENのみ、立下のみならFENのみ、両エッジならREN/FENが有効。HEN/LEN/AREN/AFENは無効。要求解放後の検出ビットは全て無効。入力パッドのヒステリシス設定自体は未読。

## OSCの電圧波形（Piイベント試行とは別時刻）

発振器出力OFFを維持して取得。CH1、×1、DC、5 Vレンジ。25 kS/s・200 msを3本、100 MS/s・50 µsを16本。全記録でLow/High遷移なし（解析閾値1/2 V）。代表レベル約2.68 V、全標本範囲2.50-2.86 V、ADCクリッピングなし。

ファイル名rise/fallはトリガ設定の名前であり、実際にそのエッジを観測したことを意味しない。AUTO取得なので静的なレベルも記録される。duty_pct=100%は解析上High判定が全標本という意味であり、発振器が100%デューティを出力したという意味ではない。

OSCはPiイベント取得と同時同期していない。全試験期間の短い変動を排除できず、発振器OFFが信号ノード0 Vを意味するわけでもない。2.68 Vとなった原因や故障箇所はこの試験だけでは確定しない。

## 結論と次の検証

回転中のファンTachや発振器の50 Hz出力を用いなくても、現在の接続条件で過剰イベントが再現した。対照試験が成立しないため、50 Hz計数へ進まず終了。次は入力の基準を明確にするため、発振器信号を切り離した既知のDC Low/High状態をOSCとPiで比較する。配線・プルアップ・測定ノードの再確認が必要。GPIOを出力へ切り替えたり、無確認に信号を短絡したりしない。

終了時は発振器CH1/CH2ともOFFを問い合わせ確認した。恒久設定やファン駆動設定は変更していない。
