# GPIO17 / GPIO18 SSH試験

実施日: 2026-09-06。接続先は試験用Pi（接続情報は公開資料に含めない）。
パスワードは本記録に保存していない。

## 接続・設定

- BCM17 = 物理11番: ファンTach入力。内部プルアップ設定は変更していない。
- BCM18 = 物理12番: C1815経由の反転PWM出力。
- 接続時は両GPIOが入力、PWMデバイス未登録。
- `sudo dtoverlay pwm pin=18 func=2` を動的にロード。
- pwmchip0/pwm0、period=40000 ns、enable=1。設定上25 kHz。
- duty_cycle=40000 nsが停止指令、0 nsが最大指令。
- ファン制御プロセスは起動していなかった。音声ドライバーsnd_bcm2835は有効だが、確認時にPCM再生デバイスの使用は認めなかった。PWMとアナログ音声の競合には引き続き注意。
- PWM周波数・電圧の実波形をオシロスコープで確認したわけではない。

## 測定結果

lgpioでGPIO17の立ち上がりを3秒間カウント。RPMは仮に2パルス/回転として `Hz × 30` で換算。

| ファン指令 | 待ち時間 | 立ち上がり数/約3秒 | 周波数 | 換算RPM |
|---|---:|---:|---:|---:|
| 0% | 3秒 | 0 | 0 Hz | 0 |
| 30% | 3秒 | 38 | 12.67 Hz | 380 |
| 60% | 3秒 | 62 | 20.67 Hz | 620 |
| 100% | 3秒 | 109 | 36.33 Hz | 1090 |
| 0% | 3秒 | 0 | 0 Hz | 0 |
| 100% 再測定 | 20秒 | 125 | 41.66 Hz | 1250 |
| 0% | 3秒 | 0 | 0 Hz | 0 |
| 100% 両エッジを取得し立ち上がりだけ計数 | 15秒 | 124 | 41.33 Hz | 1240 |
| 0% | 3秒 | 0 | 0 Hz | 0 |

最終100%試験の立ち上がり間隔中央値24.168 ms、最短24.050 ms。停止・増速・停止に信号が追従した。短い待機時間での30/60%値は定常回転数と断定しない。

## 結論と未確認点

GPIO18による制御とGPIO17のパルス入力を確認した。ただし最大回転数の校正は未完了。
ARCTIC公称400–2500 rpmに対し、2パルス/回転換算で約1240–1250 rpm。
立ち上がりのみと両エッジ取得の変更では、約半分になる問題は解消しなかった。

これだけでは電源不足、実機のパルス数、信号の取りこぼし等を特定できない。数字を公称値に合わせる目的だけで係数を変更しない。
次の確認はファン端子1–2間の運転中電圧、別の回転計または波形計測によるTachの校正。
Pi側 `vcgencmd get_throttled` は0x0だったが、これはファンの12 Vを保証しない。

参考: https://www.arctic.de/media/6f/a5/ea/1753621678/Spec_Sheet_P14_Pro_PST_EN.pdf

## 終了状態

最後の測定でTach 0パルスを確認し、停止指令を維持。PWM period=40000 / duty_cycle=40000 / enable=1。
boot設定・常駐サービスは変更していない。再起動・電源再投入時の停止は保証しない。
