# GPIO17 過剰計数：公開情報・カーネル実装の調査

調査日：2026-09-08。検索と保存済みデータ／コードの確認のみ。Piへの設定書込み、発振器の出力、追加測定、OS更新は実施していない。正式PDFは全測定後に作成する。

## 結論

GPIO割り込みの重複に関する類似報告は存在する。しかし、今回のカーネル6.18.34+rpt-rpi-v8・50 Hz入力・短時間251イベントに一致する既知不具合／修正は特定できなかった。GPIO17では計数できないという仕様上の制限や、Pythonの処理速度不足と結論する根拠もない。入力パッド・信号遷移と、カーネルの割り込み処理を切り分ける必要がある。

## 今回の証拠と限界

保存済み環境情報はPi 3 Model B Plus Rev 1.3、64-bit、gpiod 2.2.0。申告当初の3 Model Bではなく、取得済み機種情報に基づく。

- `known_input_20260908_185902/`：Piは立上りのみの取得で251イベントとなり中断。開始から処理終了まで8.570462 ms、イベント間隔中央値9.114 µs。50 Hzの20 ms周期とは一致しない。
- 直前のオシロ：50.0 Hz、Low中央値0.58 V／High中央値2.74 V。短時間高速取得では各遷移窓に1エッジ。
- ただしオシロ最終取得終了18:59:12.174、Pi開始18:59:12.787で、時間窓は重ならない。異常発生中の入力波形が正常だったとはまだ証明できない。
- OFF回復試験は立上り・立下り・両エッジ各3秒0件。内部プル無効化と信号GND修正後もON時の異常は残った。
- 保存コード `hardware/gpio17_known_input.py` は、読み出した各イベントを1行ずつ保存し、取得窓より前のイベントは除外する。単純な同じバッチの再集計は見当たらない。ただしバインディングを含めた全層の無欠陥を保証するレビューではない。

詳細は [既知50 Hz試験メモ](GPIO17_KNOWN_50HZ_2026-09-08.md) を参照。

## 公開情報との照合

### 1. Pi 3・64-bitの重複割り込み報告

[Raspberry Pi Linux issue #5214](https://github.com/raspberrypi/linux/issues/5214) は、Pi 3B・5.15.61-v8+で1 kHz入力に対し数µs後に重複割り込みが発生した報告。同じハードウェアで32-bitでは再現しなかったとの記録がある。今回と似た時間尺度だが、当時の頻度は散発的で、現カーネルや今回の大量発生を直接説明しない。32-bitへ変更すれば直るとの断定は不可。

### 2. GPIO割り込みの取りこぼしに対する修正履歴

[公式フォーラムの実験・開発者回答](https://forums.raspberrypi.com/viewtopic.php?t=350295) では、複数GPIOの近接エッジで欠落が発生し、修正PR #5457が2023年5月に統合されたと報告されている。これは主に欠落問題であり、今回の単一GPIOでの大量計数と同一ではない。古い試験用カーネルを導入する指示は採用しない。

[公開rpi-6.18.yドライバ](https://github.com/raspberrypi/linux/blob/rpi-6.18.y/drivers/pinctrl/bcm/pinctrl-bcm2835.c) の `bcm2835_gpio_irq_handle_bank()` は、イベント状態のクリアに加え、前後の入力レベル差からエッジを補完して再処理する構造を持つ。`irq_ack` 単体ではなく主ハンドラ側で確認応答する。したがって、物理エッジと上位イベントの間にはドライバ処理が存在する。ただし、この処理が今回の原因という証拠はない。参照したのは可変ブランチであり、実機バイナリに対応する正確なソースリビジョンとの照合は未実施。

### 3. 「立上りイベント」の意味

[gpiolib-cdev実装](https://github.com/raspberrypi/linux/blob/rpi-6.18.y/drivers/gpio/gpiolib-cdev.c) の `edge_irq_thread()` は、立上りのみ要求時には割り込みを立上りイベントとして分類する。両エッジ時は処理時点のレベルで分類する。このため、251件の立上りラベルや連番欠落0だけでは、251回の物理的なLow→Highを証明できない。

### 4. 入力電圧とヒステリシス

[公式GPIO仕様](https://www.raspberrypi.com/documentation/computers/raspberry-pi.html#voltage-specifications) のBCM2837系はLow最大0.9 V、High最小1.6 V（ヒステリシス有効の注記）。今回の平坦部の代表電圧はこの範囲を満たすが、遷移中の揺れは別問題。これらは保証レベルであり、個体の実際の反転電圧ではない。

同資料のPADS説明ではHYSTはbit 3、リセット値1。GPIO17を含むGPIO0〜27は共通の設定レジスタに属する。リセット値だけで現在有効とは断定できず、まず読出し確認する。アドレス表はバスアドレスのため、実機のCPU物理アドレス変換も確認してからアクセスする。共有設定を不用意に書き換えない。

## 次の切り分け案（未実施）

1. 読取りのみ：現在のHYST、カーネルパッケージ版／対応ソース、GPIO17の要求主体と割り込み割当を確認する。
2. 同時測定：Piのエッジ要求・取得が有効な時間帯にオシロ波形を取得する。取得開始直後の過剰発生を逃さないよう、先にオシロを待受けさせるなど時間窓を設計する。短い単発窓だけで全時間帯の正常性を主張しない。
3. 同じ試行でGPIO17子IRQの `/proc/interrupts` 増分、カーネルイベント列、必要に応じGPLEV読取りを比較する。親IRQは他GPIOを含み得る。IRQ計数自体も物理エッジの独立な基準ではなく、レベルポーリングも短パルスを見落とし得る。
4. 入力正常・IRQ異常が裏付けられた場合、予備SDなどで別のサポート済みカーネルを比較する。現OSを上書きせず、条件を一つずつ変える。C版取得との比較はPython層の切り分けにはなるが、同じカーネル経路を使うため独立した波形測定ではない。

GPIO17は維持できる。現接続で同時波形＋イベントの比較は計画可能だが、試験前に信号GND、R3、ファンTach切離し、入力電圧を再確認する。追加部品や配線変更の要否はその結果で判断する。フィルタで数値を整えるだけでは原因特定にならないため、現段階でデバウンス値を増やして解決扱いにはしない。
