# 市販風洞との比較に基づく制御ソフトウェアの開発優先順位

2026年10月19日。対象はPico Carrier Rev E、SDP810、BME280、INA260、ARCTIC P14 Proを備える現在の風洞。

## 推奨する開発方針

固定板の再設計を待たず、**測定条件と校正の管理 → 安定判定付き収録 → 格子測定と結果比較 → RPM一定制御 → 校正後の風速一定制御**を進める。最初の到達点は「同じ条件の試験を繰り返し、差と測定品質を説明できる装置」である。

現在のセンサー構成は、差圧・環境・回転数・ファン電力を関連付ける準定常試験に向いている。市販機の力計測、多点圧力、高速乱流測定まで一度に再現する必要はない。これらは追加機器を伴う拡張として分離する。

今回の範囲は機能調査と開発案。ファン運転、制御コード変更、CAD変更は含まない。[前日の測定原理と規格調査](README.md)を基礎とし、現行コードと最新のCFD評価を踏まえて実装順を具体化した。

## 優先順位と受入条件

工数は相対評価であり、日数の見積りではない。追加ハードなしでもソフト開発は進められるが、風速の有効範囲確定には実機校正が必要になる。

| 順位 | 実装候補 | 必要条件と規模 | 完了を判断する条件 |
|---|---|---|---|
| 1 | 測定セットアップと品質管理 | 追加ハード不要。中 | 固定板版、模型、プローブ、全圧・静圧の接続、位置、配管、断面、校正IDをrunに固定保存。変更時に適用外の校正を警告 |
| 2 | ゼロ確認と局所風速計算 | ソフトは現構成で可能。基準比較と等圧操作が必要。中 | 生差圧を残し、ゼロ・密度・補正式・係数を再現可能にする。負差圧、低差圧、範囲外を正常値に見せない |
| 3 | 安定判定付き定常測定 | 追加ハード不要。中 | 安定確認後に別の収録窓を開始。未安定の時間切れを成功としない。平均・標準偏差・傾き・有効数・欠落を保存 |
| 4 | 上昇下降試験とA/B比較 | 既存PWM試験を拡張。小〜中 | 同一条件を揃えて平均とばらつきを重ね描き。異なる校正・位置・構成を無警告で比較しない |
| 5 | 手動格子測定と断面図 | 現治具と手動移動。中 | 穴番号と実座標が一致。未測定・無効・再測定を区別し、実測点と補間図を混同しない |
| 6 | RPM一定制御 | 現Tach/PWMを利用。制御調整と検証が必要。中 | 指令追従、飽和、到達不能、Tach断を検証。PWM制限と停止保護を維持 |
| 7 | 校正済み基準風速一定制御 | 固定したプローブと有効校正。大 | 校正範囲外の指令を拒否し、センサー断・応答遅れ・到達不能で適切に停止 |
| 並行 | 結果報告と外部API整備 | 集計基盤に依存。中 | UI・CSV/JSON・PDF・APIの集計値が一致。外部公開時のTLS、接続元識別、権限、監査を検証 |

次の開発単位は**順位1〜4**が適切である。これで「設定して回す」から「条件付きで測り、前回と比較する」へ進める。格子画面は並行して模擬データで開発し、現物の座標確認後に実測へ進む。

### ゼロ確認と校正

ファン停止だけで等圧になったと決めず、両ポートの等圧条件を操作者が確認する。ゼロ値の変化を前後で記録し、過大な補正値を黙って採用しない。

風速は `U = Cv × sqrt(2 Δp / ρ)` を基本とする。SDPの信号補正と空気密度補正、プローブ係数の役割を分け、同じ補正を二重に適用しない。必要なメーカー資料と低速域の注意は[前日の調査の4章](README.md#4-既存実装と照合して見つかった重要事項)を参照する。

UIでは「差圧生値」「未検証の参考計算」「適用範囲を確認した風速」を区別する。参考計算を提供する場合も、未確認の配管や逆極性を計算で隠さず、自動風速制御には使わない。校正IDだけでなく、基準器・比較条件・範囲・不確かさの根拠を残す。NISTも基準との比較に加えて温湿度・気圧を報告している。[NIST風速校正](https://www.nist.gov/pml/sensor-science/fluid-metrology/fluid-metrology-calibration-services-air-speed)

密度1.2 kg/m³という説明用仮定では、1 m/sの動圧は0.6 Pa、5 m/sでは15 Paとなる。低速ほどゼロ誤差の相対影響が大きいため、風速の小数桁数だけで精度を示さない。

### 安定判定と統計

初期案は10秒程度の移動窓とし、差圧とRPMの変動・傾き・欠測率を確認する。窓長、連続合格時間、絶対幅と相対幅のしきい値は実機の繰返し試験で決め、設定値も保存する。安定待ちには上限を設ける。

記録する統計は、平均、標準偏差、最小・最大、有効サンプル数、欠落数、収録時間。標準偏差は時間変動の指標であり、それだけで測定不確かさではない。現行約2 Hz・SDP平均化モードの値は「低周波の時間安定性」とし、乱流強度や高速応答の指標にしない。自己相関を無視して平均の信頼区間を過小評価しない。

### 格子測定

画面には測定断面、視線方向、上下左右、穴番号、座標、挿入深さを表示する。公称80 mmの等分5×5なら壁から8・24・40・56・72 mmがセル中心だが、採用する位置はCADと現物を照合して登録する。3×3等分格子は5×5穴の単純な間引きではない。

25点を一つの測定セットとして管理し、各点は独立した有限runにする。例えば1点10秒待ち＋20秒収録でも25点で750秒に加えて移動時間が必要であり、現行1run 300秒の制限を無断で外さない。移動時は停止、位置確認、再開、安定判定の順を基本とする。中心点を途中と終了時にも測り、時間ドリフトを別に把握する。

**移動中のピトー管を風速一定制御の基準にしない。** その点の速度を同じ目標へ戻すと、元の空間分布を測れなくなるためである。初期は一定PWM、次に検証済み一定RPMを使う。一定風速下のトラバースには、移動しない独立した基準計測が必要になる。

断面平均と流量は `Q ≈ Σ(Ui Ai)`、`Uarea = Q / ΣAi` とし、角部を含む実断面に応じた面積重みを保存する。欠測点を0で埋めたり、中心1点に断面積を掛けた値を測定済み流量と表示したりしない。全断面と中央領域の均一性は別に評価し、測定点平均・面積加重平均・最大偏差の定義を明示する。

### 一定制御

RPM一定は、風洞抵抗が変化しても風速が一定になる制御ではない。安定した回転条件で比較するためのモードと位置付ける。現行Tach取得は約0.5秒窓、2パルス毎回転の仮定である。閉ループを置く場所と周期は応答試験で選び、速い制御周期にしただけで計数分解能が上がると考えない。[Pico実装](../../../Electronics/pico/firmware/control_main.py)

風速制御は固定基準点の有効風速を使い、出力上限、変化率、積分飽和防止、未到達時間制限を備える。風速一定と動圧一定は密度が変わると異なるので、初期リリースでは風速一定だけに絞り、動圧モードは実験上の必要性が出てから追加する。

## 提供する実験モード

「何を一定にするか」と「どの順で測るか」を別々に選択する。制御対象はPWM、将来RPM・基準風速。実験手順は次の構成が扱いやすい。

| モード | 操作と結果 | 初期提供の扱い |
|---|---|---|
| ライブ確認 | センサー、通信、電源、校正状態を確認 | 現行モニターを拡張。ファン操作は有限時間の枠内 |
| 単一点測定 | 位置指定、安定待ち、収録、統計 | 最優先 |
| 段階掃引 | PWMを上昇・下降させ、RPM・差圧・電力の関係を比較 | 既存レシピを拡張。風速掃引は校正と閉ループ後 |
| 格子測定 | 位置を順に案内し、分布と再現性を確認 | 模擬実装を先行し、現物位置を検証して有効化 |
| ゼロと基準比較 | 等圧確認、基準器の値を手動入力、係数と残差を確認 | 校正を承認する操作は本体側に限定 |
| A/B比較 | 模型や条件の異なる結果を同軸で比較 | 同一PWM、同一RPM、同一基準風速のどれを揃えたか明示 |
| 可視化記録 | 写真・動画の参照、時刻、模型条件、イベントを記録 | 軽量な補助機能。画像からの定量PIVは含めない |

最初のプリセット候補は、固定点の再現性、PWM上昇下降、手動25点分布の三つ。自動化しても各runの停止・異常・再開確認を省略しない。

## タッチUIとLLM向けAPI

800×480の画面は現在のナビゲーションを活かし、「運転」「実験」「結果」「設定」に情報を整理する。停止、実機か模擬か、遠隔許可、通信状態は常時表示する。市販PCソフトの細かい入力欄をそのまま縮小しない。既存の公開UI参考集（ローカル保管・公開版には未同梱）

- 運転では目標値・実測値・PWM出力を分離し、SDP、BME、INA、Tachの取得元を表示する。
- 実験では準備、位置確認、安定待ち、収録、完了を段階表示する。未安定なら理由と残り待ち時間を示す。
- 結果ではA/B曲線、段階平均とばらつき、格子図を用意する。異なる単位を同じ縦軸へ重ねない。
- 報告では目的、条件、測定元、計算法、比較結果、制限を自動挿入する。CFD、実機測定、模擬値を明確に区分する。

APIは既存のOpenAPIと認証を拡張する。次は新設候補であり、実装済みのエンドポイントではない。

| 対象 | 追加する情報と操作 |
|---|---|
| `measurement-setups` | 位置・配管・装置構成を版付きで取得。run開始時にスナップショット保存 |
| `calibrations` | 校正の範囲、係数、適用条件、未適用理由の取得。承認は本体側のみ |
| `campaigns` | 複数runを格子や反復として関連付け、次の位置と操作者確認待ちを返す |
| `results` | 統計、品質、比較条件、単位、元runへの参照、解析版を取得 |
| 既存 `capabilities` の拡張 | 「接続済み」「校正済み」「実行可能」を別に返し、使えない理由を機械可読にする |

LLMには、まず計画検証と結果読取りを提供し、操作権限がある場合だけ有限runを開始させる。遠隔ONは無期限という合意を維持する一方、許可IPとトークン、短い運転リース、300秒制限、停止時の取消は残す。LLM自身による遠隔許可・校正承認・保護解除は認めない。

外部PCから利用する工程ではTLSと接続元の認証・識別を先に設計する。リバースプロキシやSSHトンネルではアプリに見えるIPが変わり得るため、待受けを単に全インターフェースへ変えたり、転送ヘッダーを無条件に信用したりしない。現在はloopback限定であり、LAN運用完成とは扱わない。

## 固定板を変更しない間の扱い

最新の[CFD再評価](../../tests/cfd/2026-10-19_fixed_plate_refined/REPORT.md)では、固定板の定量影響を校正へ利用できる段階にはない。したがって、板の版・有無・測定面からの距離を条件として保存し、CFD由来の補正係数は実装しない。

現固定板付きのデータは、その構成における再現性・位置分布の評価に使う。板なし風洞の特性や、独立した真値を保証する校正結果とは分ける。板を後で変更したら旧校正を自動転用せず、再確認の対象とする。小型風洞ではプローブや支持物の閉塞影響も校正条件に関わる。[NISTの閉塞影響解説](https://www.nist.gov/pml/sensor-science/fluid-metrology/wall-and-blockage-effects-air-speed-calibrations)

これにより、板の再設計を待つ必要があるのは構成依存の最終校正・性能認定であり、ソフト開発全体ではなくなる。

## 追加機器が必要な将来機能

| 機能 | 追加するもの | 今は後回しにする理由 |
|---|---|---|
| 揚力・抗力・モーメント | 天秤、増幅器、支持具、荷重校正 | 現センサーでは力を直接測れない。ファン電流で代用しない |
| 模型表面の圧力分布と圧力係数 | 圧力タップ、多点差圧系または切替器、基準動圧 | SDP1台で基準と多数点を同時測定できない |
| 自動トラバース・迎角掃引 | 駆動機構、原点・限界検出、姿勢校正 | 可動範囲と衝突防止を含む機構設計が必要 |
| 乱流強度とスペクトル | 高速プローブと応答帯域を確認した取得系 | 現行2 Hzの統計とは別の測定系 |
| ヒートシンク冷却性能 | 表面温度・吸気温度、発熱量の計測と加熱保護 | BMEの環境温度とINAのファン電力だけでは熱抵抗を評価できない |

断面流量の検討には[ISO 3966:2025](https://www.iso.org/standard/86000.html)、ファン性能試験には[ISO 5801:2017と追補2025](https://www.iso.org/standard/56517.html)を参照する。5×5画面の実装だけで前者に準拠したり、PWM掃引だけで後者のファンP-Q試験になったりはしない。規格準拠を要件とする場合は本文の適用条件を別途確認する。

## 次の実装範囲案

最初のリリースを「測定セットアップ、ゼロ確認、品質付き風速計算の土台、安定判定、段階別統計、A/B比較」に絞る。模擬データで符号・低差圧・欠測・ドリフト・タイムアウト・異なる校正の混在を検証してから実機へ適用する。

この段階では固定板、配線、センサー追加を前提にしない。校正が成立していない間も差圧・RPM・電力の比較は進め、校正後に同じデータ構造へ有効な風速と断面結果を追加できる設計にする。
